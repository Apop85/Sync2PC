- Aufgabenbeschreibung:
  1. Enum `FolderLayout` (stabile Codes, nur PHOTOS): `MONTH_SUFFIX` = V1 `Jahr\MM[ - Land]`, `COUNTRY_FOLDER` = V2 `Jahr\[Land\]MM`, `COUNTRY_SUBFOLDER` = V3 `Jahr\MM\[Land]`. `of(code)` für DB-Werte; unbekannt → `MONTH_SUFFIX` nur beim Lesen aus der DB.
  2. `Profile.folderLayout: String = "MONTH_SUFFIX"`, Hilfsfunktion `layout()`. DB v8 → v9, `MIGRATION_8_9`: `ALTER TABLE profiles ADD COLUMN folderLayout TEXT NOT NULL DEFAULT 'MONTH_SUFFIX'` (DEC-084). Bestehende Profile = V1, Verhalten unverändert. `MigrationTest` 8→9 ergänzen (database-specialist).
  3. Sperre bis zum ersten Sync, technisch in der DAO: `updateProfile` als Transaktion; hat das Profil Einträge in `synced_files` oder `folder_mappings`, wird `folderLayout` aus der gespeicherten Zeile übernommen (nie überschrieben). Wird die Vorlage zulässig gewechselt: `pending_decisions` des Profils löschen. Hilfsabfrage `layoutLocked(profileId)` für die Oberfläche (-085).
  4. Sperrregel gleiches Ziel in `data/ProfileOverlap.kt`: anderes PHOTOS-Profil (auch deaktiviert, auch zum Löschen vorgemerkt bis endgültig gelöscht) mit gleichem Ziel (Vergleich wie DEC-092) und anderer Vorlage → neues Ergebnis „blockiert“ (Speichern nicht möglich, Rückgabe nennt das andere Profil und seine Vorlage). Verschachtelte Ziele → nur Warnung wie bisher. Gleiches Ziel + gleiche Quellen + andere Vorlage ist damit „blockiert“, nicht IDENTICAL.
  5. Sicherung: `BackupCodec` exportiert/importiert `folderLayout`; fehlt das Feld (alte Sicherung) → `MONTH_SUFFIX`; unbekannter Code → Profil nicht importieren, in der Importmeldung nennen (nie still V1). `BackupManager.import` „Hinzufügen“: Profile mit Sperrregel aus Punkt 4 überspringen und melden.
  6. Diagnose: Vorlage je Profil ausgeben.
