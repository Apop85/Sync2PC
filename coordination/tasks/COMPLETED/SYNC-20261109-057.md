# SYNC-20261109-057 – Rollendefinitionen: Entscheidungen an Documentation melden
- Erstellt am: 2026-11-09
- Absender: Project Manager
- Empfänger: Documentation
- Priorität: MEDIUM
- Status: COMPLETED
- Übergabegrund: Der Inhaber wünscht eine verbindliche Regel, dass getroffene Entscheidungen immer an Documentation gemeldet werden, damit `docs/DECISIONS.md` aktuell bleibt. Der Project Manager darf Dateien ausserhalb von `coordination/` nicht ändern; Rollendefinitionen sind Dokumentation.
- Aufgabenbeschreibung: In den Rollendefinitionen unter `.claude\roles\` (`Project-manager.md`, `DEVELOPMENT-Specialist.md`, `ARCHITECTURE-Specialist.md`, `QA-Specialist.md`; `DOCUMENTATION-Specialist.md` für die Empfangsseite) die Regel ergänzen, jeweils knapp und im Stil der Datei:
  - Wer eine Entscheidung trifft oder vom Inhaber erhält (Architektur, Verhalten, Sicherheitsmodell, UI-Konzept, Standardwerte, bewusst verworfene Alternativen), meldet sie Documentation per Auftrag (oder Ergänzung eines bestehenden Documentation-Auftrags) mit: Entscheidung, Begründung, verworfene Alternativen, betroffene Komponenten, Datum, Quelle (Task-ID).
  - Rollenspezifisch: PM meldet Entscheidungen des Inhabers aus der Abstimmung; Architecture Entscheidungen aus Konzepten; Development Entscheidungen, die bei der Umsetzung fallen; QA Entscheidungen zu Soll-Verhalten/Teststrategie. Nur getroffene Entscheidungen, nie offene Fragen oder blosse Vorschläge.
  - Documentation: pflegt `docs/DECISIONS.md` danach, erfindet nichts, fragt bei Unklarheit zurück.
  - Documentation erstellt bei Bedarf selbst Folgeaufträge (Matrix: nur an Project Manager, Development, Architecture), wenn eine gemeldete Entscheidung nicht nachvollziehbar ist (Begründung, Alternativen oder Quelle fehlen) oder wenn für eine Änderung am Code/Verhalten die zugehörige Entscheidung in `DECISIONS.md` fehlt. Empfänger je nach Herkunft: Entscheidung des Inhabers → Project Manager; technische Entscheidung bei Umsetzung → Development; Architekturentscheidung → Architecture. Keine Entscheidung selbst erfinden oder ergänzen, solange sie nicht bestätigt ist; Doku-Eintrag bis zur Antwort als «Entscheidung ausstehend» belassen bzw. nicht schreiben.
  Zusätzlich vorschlagen (Inhaber entscheidet): einen Satz in `CLAUDE.md` §10 oder §11 und `coordination/README.md` §2, damit die Regel auch ohne Rollen-Lesen gilt. Diese Dateien nur nach ausdrücklicher Freigabe des Inhabers ändern.
