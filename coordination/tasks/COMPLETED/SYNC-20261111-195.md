# SYNC-20261111-195 – Emojis durch eigene Icons ersetzen (Stil «Variante C Duotone»)
- Erstellt am: 2026-11-11
- Absender: UX-Specialist
- Empfänger: Development
- Priorität: MEDIUM
- Status: COMPLETED
- Übergabegrund: Der Benutzer will alle Emojis und Symbolzeichen in der Oberfläche durch eigene Icons im Stil des Hundelogos ersetzen (comichaft, verspielt, definierte Outlines). Gewählt wurde Variante C «Duotone» (dünne dunkle Outline, Farbfläche als Tönung, keine Gesichter, kein Glanzlicht). Bilddateien liegen bereit.
- Aufgabenbeschreibung: Die 16 Icons als Vektorgrafiken in die App einbinden und jeden unten genannten Emoji bzw. jedes Symbolzeichen in der Oberfläche durch das zugeordnete Icon ersetzen.
  1. Bilddateien: `.claude/ux/icons/hell/*.svg` und `.claude/ux/icons/dunkel/*.svg` (je 16, Raster 48×48, nur Pfade/Rechtecke/Kreise, Strichstärken und Farben sind festgelegt). Übersicht mit allen Icons: `.claude/ux/icons/vorschau.html` (im Browser öffnen). Gestaltungsvarianten: `.claude/AppScreenshots/icon-varianten-vorschau.html` (Variante C ist die dritte).
  2. Umsetzung als VectorDrawable (Android-Studio-Import oder von Hand), je Icon `drawable/ic_<name>.xml` (hell) und `drawable-night/ic_<name>.xml` (dunkel). Hell und Dunkel unterscheiden sich nur in Outline-Farbe und Flächentönung (siehe Tabelle Farben). Die Farbflächen verwenden `fillAlpha`.
  3. Zuordnung (Emoji/Zeichen → Icon → bekannte Fundstellen, ohne Anspruch auf Vollständigkeit; bitte per Suche vervollständigen):
     - 📁 → `ic_folder`: HomeParts.kt:535, ProfileParts.kt:49 und :146, FreeSpaceScreen.kt:360, TrashScreen.kt:137 und :249
     - 📷 → `ic_camera`: HomeParts.kt:540, ProfileParts.kt:45
     - 📱 / 💻 → `ic_phone` / `ic_pc`: ConflictScreen.kt:155 und :157
     - 🖧 → `ic_server`: ProfileParts.kt:146 (Freigaben-Liste, Wurzel)
     - ➕ → `ic_add`: ProfileParts.kt:138
     - ⬆ («..», eine Ebene höher) → `ic_upload`: ProfileParts.kt:130
     - ⏸ → `ic_pause`: strings_home.xml `home_status_paused`; ▶ → `ic_play`: Hinweise `home_pause_forever_hint`, `home_manual_only_hint` (Verweis auf das Symbol oben rechts)
     - ✓ → `ic_ok`: strings_home.xml `home_all_saved`, `home_profile_on_wifi`, `perm_granted`; strings_profile.xml `enc_test_ok`; ProfileScreen.kt:274
     - ✗ → `ic_error`: strings_profile.xml (Test-/Verschlüsselungsfehler), ProfileScreen.kt:263 und :296; Protokollzeilen in strings_engine.xml
     - ⚠ → `ic_warn`: strings_home.xml (`home_location_missing`, `home_profile_access_lost`, `home_skipped`, `home_skipped_manual`), strings_profile.xml, strings_engine.xml
     - ↻ / ↺ → `ic_sync`: `home_status_pending`, Wiederherstellen in strings_engine.xml
     - 🗑 → `ic_bin`: strings_engine.xml (Protokollzeilen `eng_trash_*`, `eng_pv_trash_*`, `eng_purged_*`)
     - ⇄ / ↔ (nur dort, wo es die Richtung «beidseitig» anzeigt, z. B. Profilkarte, ProfileOverlap.kt) → `ic_both`; ↑ / ↓ in den Protokollzeilen `eng_pv_*` → `ic_upload` / `ic_download`
     - Bleiben Text: der Pfeil → in Beschriftungen wie «Handy → PC», «App-Info → Berechtigungen» und in `direction_*` (typografisch, kein Emoji); ≤, ⤼ und ⏭ haben keine Entsprechung, Entscheidung bei Development (ersatzlos oder Text lassen), im Bericht nennen.
  4. Technik der Einbindung (Vorgabe UX, Umsetzung Development): Statt Zeichen im Text zeigt die UI vor dem Text ein Icon in einem `Row`/`InlineTextContent` (Icon 20 dp in Fliesstext der Grösse bodyMedium, 24 dp in Zeilen mit titleSmall/bodyLarge, 40 dp bei Leerzuständen). Icon und Text sind vertikal zentriert, Abstand 6 dp. Die Zeichen werden aus den Sprachdateien entfernt (beide Sprachen, danach `tools/make-translations.ps1`); wo ein String sowohl in der UI als auch in Benachrichtigungen/Diagnose-Export verwendet wird, bleibt der Text für Benachrichtigung und Export unverändert (Symbolzeichen darf dort bleiben) und die UI setzt das Icon separat. Die Entscheidung, wie Protokollzeilen (Verlauf) die Icons erhalten, trifft Development; bei Bedarf Architecture beauftragen. Der Text des Diagnose-Exports bleibt Klartext.
