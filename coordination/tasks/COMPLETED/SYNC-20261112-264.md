- Aufgabenbeschreibung: Abläufe und Regeln so ändern, dass weniger Token nötig sind, ohne merkbaren Qualitätsverlust (Beispiel des Benutzers: QA/UX prüfen mehrere Aufträge auf derselben App-Seite in einem Durchgang). Klarstellen: Änderungen an tools/ ändern die Version nicht. Regel: Rückfragen an den Benutzer immer nummeriert.
- Benutzerfreigabe: erteilt 2026-11-12, Chat Architecture
- Abhängigkeiten: SYNC-20261112-263
- Erwartetes Ergebnis: Regeln in CLAUDE.md, QA- und UX-Prompt angepasst; Liste der Änderungen nummeriert.
- Durchgeführte Arbeiten: Sicherung: coordination/archive/vor-workflow-optimierung-2026-11-12/ (CLAUDE.md, .claude/roles).
  1. QA- und UX-Prompt: «Seitenweise bündeln» als Pflicht bei mehreren Aufträgen oder Prüfpunkten (Prüfungen je App-Seite sammeln, Seite einmal ansteuern, alle Prüfungen dort erledigen, nur bei Testbedarf erneut aufrufen, Ergebnisse je Auftrag getrennt). UX: Hell/Dunkel je Seite statt je Test umschalten. QA: Testdaten einmal für alle Aufträge.
  2. QA: Testumgebung einmal je Sitzung prüfen statt je Auftrag; ein Debug-Build je Codestand für alle Aufträge; Logcat und Testausgaben nur gefiltert.
  3. CLAUDE.md §8 (alle Rollen): gebündelt arbeiten (gemeinsame Dateien/Doku-Abschnitte/App-Seiten einmal lesen bzw. ansteuern, Tests einmal); Umgebungsprüfungen und Builds einmal je Sitzung; lange Ausgaben nur gefiltert; Folgeaufträge bündeln (neue Punkte an eigenen OPEN-Auftrag an dieselbe Rolle zum selben Stand anhängen). README §5 entsprechend.
  4. CLAUDE.md §1: Änderungen an tools/ und am Regelwerk ändern die Version nicht (Benutzerentscheid 2026-11-12).
  5. CLAUDE.md §1: Rückfragen, Vorschläge und Entscheidungsvorlagen an den Benutzer immer nummeriert (Unterpunkte 1a, Varianten A/B/C), je Frage einzeln verständlich, Empfehlung bei der Nummer.
- Tests und Ergebnisse: Keine Skripte geändert. Zeilenvergleich gegen Sicherung (CLAUDE.md 6, QA 4, UX 2 Zeilen); Suche nach widersprechenden Stellen (je Auftrag prüfen, nummerierte Rückfragen, Versionsregel): keine Widersprüche.
- Verbleibende Risiken: Bündeln darf die Trennung der Ergebnisse je Auftrag nicht verwischen (ausdrücklich geregelt). Offener Vorschlag an den Benutzer: selten benötigte Teile der grossen Prompts (UX rund 18'000, QA rund 11'000 Zeichen) in Zusatzdateien auslagern, die nur bei Bedarf gelesen werden.
