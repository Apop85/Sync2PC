# SYNC-20261111-225 – Icon «Verschlüsselt» (Variante C, Schild mit Schloss) an der Profilkachel

- Absender: UX-Specialist
- Empfänger: Development

- Übergabegrund: Designentscheidung des Benutzers (Chat, 2026-11-11): Variante C, Grösse 22 dp, Anzeige klein oben rechts an der Kachel. Eine UX-Nachprüfung ist vom Benutzer nicht verlangt.
- Aufgabenbeschreibung:
  - **Neues Icon `ic_encrypted`** (Stil «Variante C Duotone», wie `ic_folder`): `drawable/ic_encrypted.xml` (Hell) und `drawable-night/ic_encrypted.xml` (Dunkel), viewport 48x48, beide Pfade mit Rundungen wie die vorhandenen Icons (strokeWidth 2.6, round/round).
    - Hell: Kontur `#FF3B2F2A`; Schild-Fläche `#FFE9954A` alpha 0.38; Schloss-Körper `#FFF7BE4F` alpha 0.38.
    - Dunkel: Kontur `#FFCFC7BE`; Schild-Fläche `#FFC49468` alpha 0.40; Schloss-Körper `#FFD6BA7C` alpha 0.40.
    - Pfade (alle ohne Füllung ausser angegeben): Schild `M24 6l15 5v12c0 9-6 15-15 19C15 38 9 32 9 23V11z` (Fläche + Kontur); Schloss-Körper `M19.5,22h9a2.5,2.5 0 0 1 2.5,2.5v5a2.5,2.5 0 0 1 -2.5,2.5h-9a2.5,2.5 0 0 1 -2.5,-2.5v-5a2.5,2.5 0 0 1 2.5,-2.5z` (Fläche + Kontur); Bügel `M20 22v-3a4 4 0 0 1 8 0v3` (nur Kontur). Referenz: `.claude/AppScreenshots/icon_verschluesselung_c_klein.html`.
  - **Anzeige:** Profilkachel auf der Startseite (HomeParts.kt), nur wenn das Profil Verschlüsselung verwendet (dieselbe Bedingung wie die bestehende Verschlüsselungsangabe der App; Development kennt sie). Ohne Verschlüsselung bleibt die Kachel wie heute, ohne Icon und ohne Platzhalter.
    - Grösse **22 dp** (fest, wächst bei grosser Schrift **nicht** mit), oben rechts in der Kachel, Abstand zum Rand 12 dp (oben und rechts).
    - **Text darf nie über das Icon ragen (Pflicht):** Der Profilname (Kopfzeile) und jede Zeile, die in die Höhe des Icons fällt, erhalten rechts mindestens 22 dp + 12 dp Rand + 8 dp Luft = 42 dp Innenabstand, am sichersten per Row mit Icon in fester Breite (Text mit `weight(1f)`), nicht per überlagertem Box-Icon. Bei langem Namen und Schrift 2,0 muss der Name umbrechen, nicht unter das Icon laufen. Zeilen weiter unten (Pfade, Richtung usw.) dürfen die volle Breite nutzen, sobald sie unterhalb des Icons beginnen; nicht darauf verlassen, dass der Name einzeilig bleibt.
    - Barrierefreiheit: `contentDescription` aus neuem String `icon_encrypted` (DE «Verschlüsselt», EN «Encrypted»), in beide Sprachdateien (`values/`, `values-de/`), danach `tools/make-translations.ps1`.
  - Nicht Teil des Auftrags: Symbole im Text (`SymbolText.kt`-Map) und andere Bildschirme.
- Erwartetes Ergebnis: Icon-Dateien, Anzeige an der Kachel, Strings in beiden Sprachen, PATCH in `version.properties` erhöht; Doku-Übergabe (sichtbares Verhalten) an Documentation.

- Übernahmebestätigung: Auftrag des Benutzers im Chat, 2026-11-11
- Ergebnis (2026-11-11, Version 0.16.20): Icons drawable/ und drawable-night/ic_encrypted.xml, String icon_encrypted (EN/DE), Anzeige in HomeParts.kt als letztes Element der Kopfzeile (Row, 22 dp fest, optisch 12 dp Rand, 8 dp Luft; Text weight(1f), bricht um). Auf Benutzerwunsch (Chat) zeigt das Icon den **tatsächlichen Zustand**, nicht die Einstellung: neues smb/EncryptionStatus.kt hält nach jeder erfolgreichen Anmeldung (SmbSession.open) fest, ob die Sitzung wirklich verschlüsselt war (smbSessionEncrypted); SharedPreferences «enc_status», kein DB-Schema. Gilt nur für dieselbe Einstellung/Freigabe/denselben Unterordner, sonst unbekannt = kein Icon. Vor der ersten Verbindung (oder nach Änderung) erscheint kein Icon; Anzeige = Stand der letzten Anmeldung. Nebenbei: Zeile Profilkarte-Pfad (B2b, -222) in Hilfsfunktion pathBreakAfterBackslash (Common.kt) ausgelagert, unsichtbare Zeichen im Quelltext durch Escapes ersetzt.
- Tests: keine ausgeführt, nicht kompiliert (Gradle-JVM 8, JDK 17 fehlt in der Umgebung), Emulator nicht benutzt. Kein Unit-Test für EncryptionStatus.
